# NetSwitch — 内网 IP / 网关 / DNS 多套配置一键切换

一个零依赖的 Windows 小工具：把常用的几套网络参数（IP、子网掩码、网关、DNS）存成「配置集」，需要切换时点一下就好，不用再去「网络和 Internet 设置」里一层层点。

纯 PowerShell + WinForms 实现，**不需要安装 Python / Node / 任何第三方库**，Windows 8 / Server 2012 及以上（含 Win10 / Win11）直接可用。

---

## 一、文件说明

| 文件 | 作用 |
| --- | --- |
| `NetSwitch.ps1` | 主程序（图形界面 + 命令行双模式），**核心文件** |
| `NetSwitch.bat` | 双击启动器，同目录下双击即可打开界面 |
| `profiles.json` | 你的配置集数据，**首次运行后自动在同目录生成** |
| `profiles.bak-yyyyMMdd-HHmmss.json` | 每次保存配置前自动复制的上一份配置，保留最近 5 份（见第十一节） |
| `applied-routes.json` | 记录本程序自己添加过的附加路由，下次切换前据此自动清理（自动生成，无需手工编辑） |
| `backups\` | 切换前自动生成的网络状态备份，最多保留 10 份（见第七节） |
| `profiles.example.json` | 示例配置，可通过「导入配置」直接体验字段写法 |
| `README.md` | 本文档 |

> 除 `backups\` 是子目录、`profiles.example.json` 是随包附带的示例外，上面这些文件都在**脚本同目录**下自动生成，不需要手工创建。

## 二、快速开始

### 方法 1：图形界面（推荐）

1. 把整个文件夹拷到本地任意位置，例如 `D:\Tools\NetSwitch\`
2. 双击 **`NetSwitch.bat`**
3. 点左下角 **「新建」**，填一个名称（如「研发内网」）
4. 在编辑器里选中本机网卡，点 **「+ 添加网卡行」**，程序会自动把该网卡当前的 IP / 掩码 / 网关带出来，直接改成目标值即可
   - 新建时编辑器会**自动预置一行**，打开就能直接在表格里输入 IP / 掩码 / 网关 / DNS（点一下就进入编辑）
   - 网卡下拉框里只列出**物理网卡**，VMware / 蓝牙等虚拟网卡默认不出现（见第十节）
5. 点 **「保存」** → 选中该配置集 → 点 **「应用此配置集」**
   - 不确定会改到哪几块网卡？先点 **「预览此配置集」**，它只写日志、不动网络

> **修改 IP 需要管理员权限。** 首次点「应用」时会弹 UAC 授权；也可以直接右键 `NetSwitch.bat` → **以管理员身份运行**，界面右上角会显示绿色的「已获得管理员权限」。

### 方法 2：桌面快捷方式（最省事）

在界面里选中某个配置集，点 **「生成桌面快捷方式」**，桌面上会多一个 `NetSwitch-<配置集名>.lnk`。

以后**双击这个图标就等于切换**（快捷方式已预先标记「以管理员身份运行」，双击直接切换，不再有额外的麻烦步骤）。这是给最常用的两三套环境准备的。

> **快捷方式是按「配置集名称」绑定的**，所以有两个前提：
> - **改了配置集的名字** —— 程序会自动把桌面上的旧快捷方式改名并指向新名字。万一同步没成功，回界面重新点一次「生成桌面快捷方式」即可。
> - **挪动了脚本位置** —— 快捷方式里存的是 `NetSwitch.ps1` 的绝对路径，脚本一搬家旧快捷方式就打不开了，需要按新位置重新生成。
>
> 双击失败时会**弹出提示框**并列出当前可用的配置集名称，不会再像以前那样「双击了毫无反应」。详细过程仍记录在 `NetSwitch.log`。

### 方法 3：命令行 / 脚本调用

```powershell
powershell -ExecutionPolicy Bypass -File NetSwitch.ps1 -ListProfiles    # 列出所有配置集
powershell -ExecutionPolicy Bypass -File NetSwitch.ps1 -ListAdapters    # 列出本机网卡名
powershell -ExecutionPolicy Bypass -File NetSwitch.ps1 -ShowStatus      # 查看当前 IP/网关/DNS
powershell -ExecutionPolicy Bypass -File NetSwitch.ps1 -Apply "研发内网" # 直接切换
powershell -ExecutionPolicy Bypass -File NetSwitch.ps1 -Apply "研发内网" -Silent  # 切换后不暂停
powershell -ExecutionPolicy Bypass -File NetSwitch.ps1 -ExportFile backup.json
powershell -ExecutionPolicy Bypass -File NetSwitch.ps1 -ImportFile team.json
```

`-Apply` 时如果发现不是管理员，会**自动弹 UAC 提权**并继续完成切换，无需手动右键。

> `-ListAdapters` 与 `-Apply` 走的是同一套网卡匹配逻辑，因此**同样默认排除虚拟网卡**（见第十节）。命令行下没有勾选框可切换，需要纳入虚拟网卡时请把脚本里的 `$script:ExcludeVirtualAdapters` 改为 `$false`。

- 每次「应用此配置集」之前，程序会**自动把当时的网络参数存成一条备份**，可从「备份记录」里找回（见第七节）

## 四、字段填写说明

**在哪里填？** 打开「新建配置集」后，上半部分填**名称 / 说明**，下半部分的**表格就是填 IP 的地方**：
点表格里的一格直接输入，最左侧「启用」列打勾表示该行生效。新建时程序会先放好一行，
跟着表头从左到右填下去即可：`网卡名称 → 获取方式 → IP 地址 → 子网掩码 → 网关 → 默认跃点 → DNS → 附加路由`。

一条网卡记录包含这些字段：

| 字段 | 说明 |
| --- | --- |
| 启用 | 不勾选则该网卡在切换时被跳过 |
| 网卡名称/匹配 | **照常填网卡名即可**（如 `以太网`）。程序会自动按 **MAC 地址**记住这块网卡，界面上仍显示名称 —— 以后在系统里给网卡改名也不会失效。也可用 `*` 表示全部网卡、`以太网*` 这类模糊匹配。**默认只匹配物理网卡**，虚拟网卡被过滤掉（见第十节） |
| 获取方式 | `静态IP` 或 `DHCP自动` |
| IP 地址 | 静态模式下必填 |
| 子网掩码 | 支持 `255.255.255.0` 或前缀长度 `24`，留空默认 `/24` |
| 网关 | 多个用分号隔开，可指定跃点数：`192.168.1.1;10.0.0.1:20`（冒号后为跃点数，越小优先级越高） |
| 默认跃点(可选) | 默认路由的 metric，**留空为自动**。合法值 0~9999，越小优先级越高（见下方说明） |
| DNS 服务器 | 多个用分号隔开；**留空表示自动获取** |
| 附加路由 | 可选，`目标网段>下一跳`，如 `172.16.0.0/12>10.10.20.254`，多条用分号隔开 |

> 组合用法：获取方式选 `DHCP自动` 但 DNS 里填了地址，则 IP 自动获取、DNS 固定为指定服务器 —— 这在公司内网里很常见。

**关于「默认跃点」**

默认路由的跃点数（metric）越小优先级越高。它的典型用途是：本机 WLAN 的 DHCP 默认路由 metric 为 0、比以太网静态网关更优先时，给以太网填一个更小的跃点数（如 `0` 或 `1`），就能把默认出口压回内网网卡。

优先级规则（三选一，自上而下）：

| 优先级 | 来源 | 例子 |
| --- | --- | --- |
| 1（最高） | 网关串里写的跃点数 | 网关填 `192.168.1.1:10` → metric = 10 |
| 2 | 网卡的「默认跃点」列 | 默认跃点填 `1` → metric = 1 |
| 3（最低） | 自动分配 | 多个网关时按 `10、11、12…` 逐个 +1 |

填了「默认跃点」后，程序会改成「先建 IP 地址、再手工建默认路由」的方式下发，因为带 `-DefaultGateway` 的命令会强行使用系统默认 metric、覆盖不掉。

**关于「附加路由」**

- 下一跳必须与网卡 IP 处于**同一网段**，否则路由会添加失败（失败原因会写进日志，切换本身继续）。
- 程序会把**自己添加过的**路由记到 `applied-routes.json`，下次切换同一块网卡前先按记录删一遍。这样在配置集里删掉某条路由后再切一次，系统里就不会残留旧路由。
- 只删 NetSwitch 自己加过的路由，**绝不会动系统或你手工添加的路由**。记录文件损坏时按「没有记录」处理，最坏结果只是漏清一次。

**关于「网卡名称/匹配」**

这一列**照常填网卡名就行**，不用去查 MAC —— 程序会在保存时自动把它换成那块网卡的 MAC 地址存起来，
界面上仍然显示网卡名。既好认，又不怕改名：

```
你填「以太网」  →  实际存 B0-25-AA-6F-36-44  →  界面仍显示「以太网」
```

以后在 Windows 里把网卡改名叫「内网」，配置集照样能匹配上（MAC 没变），界面上也会跟着显示「内网」。

匹配时按三级顺序查找，命中即停：

| 级别 | 匹配依据 | 示例 |
| --- | --- | --- |
| 1 | 网卡名称（精确） | `以太网` |
| 2 | 网卡名称（模糊） | `以太网*`、`以*` |
| 3 | 硬件描述 / MAC 地址 / InterfaceGuid | `Realtek`、`B0-25-AA-6F-36-44` |

MAC 的三种写法完全等价：`B0-25-AA-6F-36-44`、`b0:25:aa:6f:36:44`、`B025AA6F3644`。
GUID 支持完整值或前缀（如 `539D937E`）。

**什么时候不会自动转成 MAC？** 只有「这个值唯一匹配一块网卡」时才转换。以下几种情况保持原样，是刻意的：

| 情况 | 例子 | 原因 |
| --- | --- | --- |
| 通配符 | `*`、`以太网*` | 转换会破坏通配语义 |
| 匹配到多块网卡 | 模糊匹配命中 2 块以上 | 无法确定该记哪一块 |
| 匹配不到 | 名字写错、网卡当前不在本机 | 保留你填的值，方便日后修正 |

## 五、分享给同事

方式很简单：把 `NetSwitch.ps1` 和你的 `profiles.json`（或导出的一份 json）一起发过去，对方双击 `NetSwitch.bat` 就能用。若不想发文件，也可以导出 json 让对方「导入配置」。

同事机器上的网卡名若不一样，在编辑器里改「网卡名称」即可；更省事的办法是把这一列填成模糊匹配，比如 `以太网*`。

## 六、常见问题

**1. 双击 bat 一闪而过 / 提示「禁止运行脚本」**

系统执行策略限制。解决方式任选其一：

- 用 `NetSwitch.bat` 启动（它内部已经带了 `-ExecutionPolicy Bypass`）
- 或在 PowerShell 里执行一次：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

**2. 提示需要管理员权限**

修改 IP、网关这类操作必须是管理员。右键 `NetSwitch.bat` → 以管理员身份运行即可；或在界面右上角点「提权并重启」。

**3. 中文显示乱码**

`NetSwitch.ps1` 已按 **UTF-8 BOM** 保存，Windows PowerShell 5.1 下不会乱码。如果自己用记事本改过并另存为 ANSI，可能会异常，建议用 VS Code 保存为「UTF-8 with BOM」。

**4. 切换后网络短暂断开**

正常现象。网卡 IP 变更时会断一下，通常 1~3 秒恢复。日志里没有红色报错即可。

**5. 想保留当前网络配置怎么办**

先在界面里「新建」一个配置集，添加网卡行时程序会自动把当前 IP / 掩码 / 网关带出来，改名保存即可 —— 相当于把当前状态存档了。

**6. 会不会把 `profiles.json` 写到奇怪的地方**

不会。默认读写脚本同目录的 `profiles.json`；只有在同目录不可写时才回退到 `%APPDATA%\NetSwitch\profiles.json`。也可以用 `-ConfigPath 路径` 显式指定。

**7. 打开界面后「操作日志」为什么是空的**

现在打开界面会自动把最近的日志（含本次启动记录）回填进日志框，并追加一条「界面已就绪」，不会再出现空白面板。若仍然为空，说明日志目录不可写，可到脚本同目录查看是否有 `NetSwitch.log`。

**8. 编辑窗口里表格是空的，IP 填在哪**

在表格里填。点 **「+ 添加网卡行」** 会出现一行，然后点某个单元格直接输入即可；新建时程序已经先放好一行，打开就能填。最左侧「启用」列打勾表示该行生效。

**9. 双击桌面快捷方式没反应 / 提示「找不到配置集」**

快捷方式里存的是**生成那一刻的配置集名称**。如果后来把配置集改了名，快捷方式里的旧名字就找不到对象了 —— 程序现在会在改名时自动同步，若仍遇到，回界面重新点一次 **「生成桌面快捷方式」** 即可。

另一种情况是**挪动了 `NetSwitch.ps1` 的位置**：快捷方式指向的是绝对路径，脚本搬家后旧快捷方式会失效，需在新位置重新生成。

从 v1.0.0 起，这类失败都会**弹窗提示**并列出当前可用的配置集名称，不再静默无反应。另外快捷方式参数里带 `-Silent`，切换成功后不会残留挂起的后台进程。

**10. 应用时提示「没有匹配到任何可操作的网卡，已中止」**

程序会在真正动手前先算一遍命中范围，命中 0 块就中止，不会误改网络。常见原因：

| 原因 | 处理办法 |
| --- | --- |
| 配置集里的网卡条目全部处于「停用」状态 | 在编辑器里把需要行的「启用」勾上 |
| 网卡匹配名写错，本机没有同名网卡 | 用 `-ListAdapters` 看一眼真实网卡名，或改成模糊匹配如 `以太网*` |
| 目标网卡被虚拟网卡过滤规则挡掉了 | 在主界面左下角勾选「包含虚拟网卡（VMware/蓝牙等）」后再试（见第十节） |

想先验证而不动网络，点 **「预览此配置集」** 即可看到它会命中哪几块网卡。

**11. 写入静态 IP 时弹出「IP 可能已被占用」**

这是切换前的**尽力而为**探测：程序先清掉该地址的 ARP 缓存，再发一次短超时 ping，最后回查 ARP 表看是否有人应答。只有「ping 通」或「确实解析出 MAC」才会提示。

- 它**只警告、不强制阻断**：弹窗里选「是」会照常写入，选「否」只跳过这一块网卡。
- 存在误报：对方关机、静态 ARP 项、禁 ICMP 但会应答 ARP 的主机、虚拟网卡都可能触发。确认地址确实没人用，选「仍然继续」即可。
- 探测只在图形界面下弹窗；命令行 / 桌面快捷方式（`-Silent`）下只写日志并继续，避免隐藏窗口卡住。

**12. 配置集里删掉附加路由后，系统里那条还在**

用 `route print` 看到的残留路由是 NetSwitch 上一次加的。现在程序会把加过的路由记进 `applied-routes.json`，**下次切换同一块网卡前自动清掉**。若想立刻手动清除，可再切换一次该配置集，或在管理员 PowerShell 里自行 `route delete`。

**13. 切换后能上网但走的不是内网网关**

多块网卡都有默认路由时，Windows 按 metric（跃点数）挑优先级。给内网网卡填一个更小的「默认跃点」（如 `0` 或 `1`）即可把出口压回去，详见第四节「关于『默认跃点』」。

## 七、切换前的自动备份

切换配置集时，程序会先清掉网卡上现有的 IPv4 地址和默认网关，再写入新参数。为防手滑，**每次点「应用此配置集」之前，它都会自动把当时的网络状态存成一份备份**，不需要任何手工操作。

| 项目 | 说明 |
| --- | --- |
| 存放位置 | `profiles.json` 同级的 `backups\` 子目录，文件名如 `NetSwitch-backup-20261010-143052.json` |
| 保留份数 | 最近 **10** 份，超出后自动删掉最旧的 |
| 备份内容 | 每块网卡当时的获取方式（静态 / DHCP）、IP、掩码、网关、DNS，格式与 `profiles.json` 完全一致 |
| 查看方式 | 主界面点 **「备份记录」**，可看到全部备份、打开备份目录 |
| 恢复方式一 | 在「备份记录」里选中一条，点 **「导入为配置集」**，它就会出现在左侧列表里；再对它点「应用此配置集」即可切回当时的状态 |
| 恢复方式二 | 在「备份记录」里选中一条，点 **「还原此备份到网卡」**，直接把备份写回网卡，不用先导入成配置集 |

### 「还原此备份到网卡」（一键还原）

| 项目 | 说明 |
| --- | --- |
| 权限 | 需要**管理员权限**。非管理员时会先询问是否提权重开程序，选否则取消 |
| 执行前确认 | 先读出备份并按本机现有网卡做匹配，弹窗**列出将被改动的网卡名**；一份都没匹配上就提示「无法还原」并放弃 |
| 还原前再备份 | 还原同样会先清空网卡地址，所以动手之前会**再把当前网络状态存一份新备份**，万一还原错了还能回退 |
| 结果 | 逐块网卡写入，全部成功记 `OK`；有失败则记明是哪块网卡、什么原因 |

> 两种方式怎么选：想保留这份状态当长期配置集（可反复切换）用**导入为配置集**；只是想立刻回到当时的网络、不留额外条目，用**还原此备份到网卡**。

两点说明：

1. 备份**只在切换前**（以及上面的一键还原前）生成。纯查看（「刷新状态」、「预览此配置集」）不写任何文件。
2. 自动获取（DHCP）的网卡不记录具体 IP，只记「自动获取」——因为这类地址是路由器分配的，写死反而会出问题。**手动设置的静态地址会被完整记录**，这正是最需要找回的部分。

> 想手动留一份长期存档，仍然可以用「导出配置」另存为指定文件。

## 八、日志与出错求助

工具会自动写日志，不用额外配置：

| 项目 | 说明 |
| --- | --- |
| 日志位置 | 脚本同目录的 **`NetSwitch.log`** |
| 记录内容 | 启动时的环境快照（系统 / PowerShell 版本 / 是否管理员 / 配置文件路径）、每次切换做了什么、每一步是否失败、失败的具体原因 |
| 界面查看 | 主界面右下角「操作日志」面板实时显示；**打开界面时会自动回填启动记录**，窗口关闭也不会丢 |
| 自动清理 | 超过 1MB 时只保留最近 500 行，不会无限增长 |
| 快速导出 | 点右下角 **「复制日志」**，自动把最近 300 行复制到剪贴板 |

**出错时怎么反馈**（推荐顺序）：

1. 在界面点 **「复制日志」**，把内容直接粘贴过来 —— 里面已经有环境信息和出错行
2. 若界面打不开，直接去脚本目录找 **`NetSwitch.log`**，把最后几十行发来
3. 命令行模式同样会写日志：`NetSwitch.ps1 -Apply "配置集名"` 之后查看日志文件

日志里会包含你的内网 IP 和 Windows 用户名，贴给别人之前留意一下是否需要脱敏。

## 九、安全提示

程序执行的所有底层命令都是 Windows 自带的 `NetTCPIP` 模块 cmdlet（`Get-NetAdapter`、`New-NetIPAddress`、`Set-NetIPInterface`、`Set-DnsClientServerAddress`、`New-NetRoute`、`Remove-NetRoute` 等），不涉及第三方驱动或注册表修改。切换前会清除网卡上已有的 IPv4 地址与默认网关。

为降低误伤风险，程序内置了三道保险：

| 保险 | 说明 |
| --- | --- |
| 虚拟网卡过滤 | 默认只操作物理网卡，VMware / 蓝牙 / 环回等不会被动到（见第十节） |
| 应用前确认 | 「应用此配置集」会先列出本次将改动的网卡及当前 IP，命中 0 块则直接中止 |
| 自动备份 | 切换前（以及一键还原前）自动存一份网络状态，`profiles.json` 每次保存前也自动留档（见第七、十一节） |

程序不会去动它自己没添加过的路由，也**不会**把虚拟网卡刷成 DHCP。但**第一次使用前建议仍然先手工建一个配置集把当前环境存下来**，这样最稳妥。

## 十、虚拟网卡过滤（默认排除 VMware / 蓝牙等）

**这是本项目最重要的一条行为变更，请务必先看一眼。**

机器上通常同时存在 VMware / VirtualBox / Hyper-V 虚拟网卡、蓝牙网卡、环回适配器，以及手机热点共享出来的「本地连接\*」。如果配置集里把网卡名写成 `*`，不加过滤就会把这些网卡一并刷成 DHCP，**直接破坏虚拟机网络并踢掉无线**。

所以现在 `Get-AdapterList` 默认**排除虚拟与非物理网卡**。本机实测效果：

| 结果 | 网卡 |
| --- | --- |
| 保留（命中 2 块） | 以太网、WLAN |
| 排除（命中 3 块） | VMware Network Adapter VMnet1、VMware Network Adapter VMnet8、蓝牙网络连接 |

排除规则由脚本里的 `$script:VirtualAdapterPatterns` 定义，按**网卡名称**和**网卡描述（InterfaceDescription）**做不区分大小写的 `-like` 通配匹配，覆盖：

| 规则 | 对应网卡 |
| --- | --- |
| `*VMware*` / `*VMnet*` | VMware Workstation 虚拟网卡（含名称里不含 VMware 的 VMnet1 / VMnet8） |
| `*VirtualBox*` | VirtualBox Host-Only / Bridged |
| `*Hyper-V*` / `*HyperV*` | Hyper-V 虚拟交换机 |
| `*Bluetooth*` / `*蓝牙*` | 蓝牙网络连接 |
| `*Loopback*` / `*环回*` | 环回适配器 |
| `*本地连接*` | 手机热点 / 网络共享产生的「本地连接\*」 |
| `*Teredo*` / `*isatap*` | IPv6 隧道伪接口 |
| `*WAN Miniport*` | 广域网微型端口，非真实物理网卡 |

除此之外，网卡对象自带 `Virtual` 标记且为 `$true` 时也会被排除。

### 请特别注意这两点

1. **配置集里网卡名写成 `*` 的（例如默认的「DHCP 自动获取」），过去会波及所有网卡，现在只会作用于物理网卡。**
2. **WLAN 是真实物理网卡，默认不排除**，所以 `*` 仍然会匹配到它 —— 想只改有线网卡，就把网卡名写成 `以太网` 或 `以太网*`，不要写 `*`。

被跳过的网卡会记一条 INFO 日志，形如：`已跳过 3 块虚拟/非物理网卡（…）。如需把它们也纳入管理，请在主界面勾选「包含虚拟网卡」…`

### 如何关闭过滤

| 方式 | 操作 | 生效范围 |
| --- | --- | --- |
| 图形界面（推荐） | 主界面左下角勾选 **「包含虚拟网卡（VMware/蓝牙等）」** | 仅当前进程，不写回脚本，重启界面后恢复默认 |
| 改脚本 | 把 `$script:ExcludeVirtualAdapters` 改成 `$false` | 永久生效 |
| 增减规则 | 直接编辑 `$script:VirtualAdapterPatterns` 数组 | 永久生效 |

> 过滤对「应用」「预览」「备份还原」同样有效：它们都用同一套匹配逻辑（`Find-MatchedAdapters`），所以预览里看到的命中结果就是真正应用时的结果。

## 十一、profiles.json 的自动备份

每次保存配置（新建、编辑、删除、导入等任何写回 `profiles.json` 的操作）之前，程序会先把现有文件复制一份再覆盖写：

| 项目 | 说明 |
| --- | --- |
| 文件名 | `profiles.bak-yyyyMMdd-HHmmss.json`，与 `profiles.json` 同目录 |
| 保留份数 | 最近 **5** 份，超出后按文件名倒序自动删除最旧的 |
| 清理范围 | 只删严格匹配 `profiles.bak-8位日期-6位时间.json` 的文件，不会误伤同目录里名字相近的其它文件 |
| 失败处理 | 备份失败只记一条 WARN 日志，**不影响本次保存**；主流程照常写盘 |

想回滚时，把某份 `profiles.bak-*.json` 改名为 `profiles.json`（或用 `-ConfigPath` 指向它）即可。

> 这一层备份管的是**配置集文件本身**（写坏了、误删了配置集）；第七节那层备份管的是**网络状态**（切换前当前 IP 是什么）。两者互不替代。

## 十二、网卡在系统里改名了怎么办

**现象**：在 Windows 里把网卡重命名（如「以太网」→「内网」）后，原配置集点「应用」会提示
「没有匹配到任何网卡」—— 因为配置集里存的还是旧名字，按名称匹配必然落空。

| 处理方式 | 适用场景 | 操作 |
| --- | --- | --- |
| **自动重新绑定（推荐）** | 已经改名，想立刻修好 | 点「应用此配置集」或「预览此配置集」→ 弹窗问「是否现在重新绑定」→ 选「是」→ 在对话框里挑一块本机网卡 → 点「绑定」。**一次点击即可走完「重绑 + 应用」** |
| **预防：改用稳定标识** | 还没改名，想提前免疫 | 把配置集里的「网卡名称/匹配」改成硬件描述或 MAC 地址（见第四节）。以后改名也不受影响 |
| 手工修改 | 想换绑到别的网卡 | 编辑配置集，把「网卡名称/匹配」直接改成新值 |

重新绑定对话框的要点：

- 上半部分列出该配置集里的**网卡条目**，下半部分列出本机的**真实网卡**（已排除虚拟网卡），
  每行显示 `名称  |  硬件描述  |  MAC`。
- 一律**按 MAC 地址记录**，界面上仍显示网卡名称（见第四节），所以不需要你做选择。
- 绑定后立刻写回 `profiles.json`，并自动生成一份 `.bak` 备份可回滚。
